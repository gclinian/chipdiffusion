我之前一直以為 ddpo 是在 inference 時進行強化學習，但我剛剛看到 report 說 你是用 ddpo 對 pretrain model 做微調，我有哪裡理解錯誤

你的理解沒有錯——DDPO 確實是在 training 階段對 pre-trained model 做微調，不是 inference 時。

可能讓你混淆的是：DDPO 的 training 過程包含了 inference（reverse sampling）。每個 training step 的流程是：

做一次完整的 reverse sampling（跟 inference 一樣，從 noise 生成 placement）
計算生成結果的 reward（HPWL）
用 policy gradient 更新模型權重
所以它不是傳統的「拿 ground truth 算 MSE loss」的 supervised training，而是「讓模型自己生成，再根據結果好壞調整」。但本質上還是在改模型權重（fine-tuning），跑完後你會得到一個新的 checkpoint。

Inference 時跟原本一樣，就是正常的 reverse sampling + guidance + legalization，沒有 RL 的部分。

真的假的？我以為 ddpo 是在 inference 時的 guidance 時用到 RL 的技術？

不是的，DDPO 是 training-time 的方法。讓我釐清兩個容易混淆的東西：

Guidance（inference 時）：

在 reverse sampling 的每一步，用 HPWL/legality 的梯度去「推」生成結果往更好的方向
不改模型權重，只改當下的 sampling 軌跡
這是 ChipDiffusion 原本就有的，在 guidance.py 裡
DDPO（training 時）：

讓模型做 reverse sampling → 算 reward → 用 policy gradient 更新模型權重
改模型權重，目標是讓模型「學會」直接生成更好的 placement
來自 Black et al. 2023 的論文 "Training Diffusion Models with Reinforcement Learning"
兩者可以疊加使用：先用 DDPO fine-tune 出一個更好的 model，inference 時再加上 guidance 進一步改善。

所以如果你原本想要的是「inference 時用 RL 技術改善 guidance」，那 DDPO 不是你想的那個。你是想要改善 inference 階段的 guidance 策略嗎？還是 DDPO 這個 fine-tuning 方向也可以接受？

DDPO	Policy gradient fine-tuning	是（training）

我好奇為什麼可以用 ddpo 去 finetune diffusion model? diffusion model 不是 policy network 啊？

好問題。關鍵在於 DDPO 把 diffusion model 的 reverse process 重新詮釋成 RL 的 MDP：

RL 概念	對應到 Diffusion
Agent / Policy	Denoising network（就是 diffusion model 本身）
State	當前 timestep 的 noisy sample x_t
Action	模型預測的 noise ε（決定怎麼 denoise）
Trajectory	整個 reverse process（x_T → x_{T-1} → ... → x_0）
Reward	只在最後一步給（最終 x_0 的 HPWL）
Diffusion model 在每個 timestep 接收 noisy state x_t，輸出一個 noise 預測 ε，這個預測決定了下一步 x_{t-1} 是什麼。這就是 policy 在做的事——看到 state，決定 action。

而且因為 reverse sampling 有加入隨機 noise（z），所以它是 stochastic policy，每次生成的結果不同。這讓我們可以算 log probability：

log π(action | state) = log p(x_{t-1} | x_t, μ, σ)
ddpo.py 裡的 pi_log_prob(x, mu, sigma) 就是在算這個。有了 trajectory log prob 和 reward，就能用標準的 policy gradient：

loss = -E[log π(trajectory) × advantage]
所以 diffusion model 本來就不是 policy network，但 DDPO 透過這個重新詮釋，把它當作 policy network 來做 RL fine-tuning。數學上是自洽的。

原來如此，所以說 diffusion model 在 inference 時也能想成是 RL inference 嗎

可以這樣看，但要注意差別：

正常 diffusion inference：model 在每步預測 noise，用固定的 sampling 公式算出 x_{t-1}。這等同於一個 pre-trained policy 在 rollout——不學習、不更新，就是按照學到的策略執行。

加上 guidance 後：每步除了 model 預測外，還加上 HPWL/legality 的梯度去修正 x_{t-1}。這就像是在 rollout 時加了一個 reward shaping，用即時的 reward signal 去推 trajectory 往更好的方向走。

用 RL 的語言對照：

Inference 做法	RL 類比
無 guidance 的 sampling	Policy rollout（純執行）
有 guidance 的 sampling	Policy rollout + reward shaping / planning
Multi-sample best-of-N	多次 rollout 取最高 return
DDPO fine-tune 後再 inference	用更好的 policy 做 rollout
所以是的，inference 可以想成 RL 的 rollout。但嚴格來說，普通的 guided sampling 不算 RL，因為它沒有在做 policy improvement——它更接近 planning（在已知 reward function 下搜索更好的 trajectory）。真正的 RL 是像 DDPO 那樣把經驗回饋到模型權重裡。

等等，如果說可以在 training 時用 reward fintuning diffusion model，那在 inference 時為什麼不能用 reward 來做 RL?

其實可以，而且 guidance 本質上就在做類似的事。差別只在於你優化的是什麼：

優化什麼	方法
Training RL (DDPO)	模型權重 θ	跑完 trajectory → 算 reward → 更新 θ
Inference guidance	當前 trajectory 的 x_t	每步算 reward 梯度 → 直接修正 x_t
Guidance 就是在 inference 時用 reward（HPWL, legality）的梯度去直接改 trajectory，而不是改模型權重。你可以把它想成：

DDPO：「我改善 policy，讓它以後每次都生得更好」
Guidance：「我不改 policy，但這次生成的過程中我一路用 reward 去推它」
那你會問：既然 inference 時已經有 reward signal，為什麼不直接在 inference 時做 RL 更新權重？

技術上可以（這就是 test-time training 的概念），但實際上不划算：

每個新 circuit 都要重新跑 RL 更新權重，很慢
Guidance 直接改 trajectory 更快——不需要多輪 rollout，一次 inference 就能用上 reward
所以目前的做法其實是合理的分工：DDPO 在 training 時改善模型的「底子」，guidance 在 inference 時針對特定 circuit 做即時優化。兩者可以疊加。

解釋什麼是 val loss和catastrophic forgetting

Val Loss（Validation Loss）

Val loss 是用 supervised 方式衡量模型的 denoising 能力。具體來說：

拿一個乾淨的 placement，加上已知的 noise
讓模型預測這個 noise
預測的 noise 跟真實 noise 的 MSE 就是 val loss
Val loss 低 = 模型能準確地去噪 = denoising 能力好。這是 diffusion model 的「本職工作」。

Catastrophic Forgetting

指模型在學新東西時，把原本學會的能力忘掉了。

在我們的情況：

Pre-trained model 原本很會 denoising（val loss = 0.17）
DDPO 教它「生成低 HPWL 的 placement」
模型發現：不需要好好 denoise，直接輸出一個固定的低 HPWL pattern 就能拿到高 reward
結果：reward 改善了（-241 → -102），但 denoising 能力被毀了（val loss 0.17 → 130,000）
類比：一個書法家（pre-trained model）被要求寫出筆劃最少的字（HPWL reward）。他發現隨便畫一條線就能「得分最高」，於是忘記怎麼寫字了。

這就是為什麼 DDPO 的 eval 結果好壞參半——模型的基礎能力被破壞了，有些 circuit 碰巧變好，有些就變差。

我還想知道這裡 ddpo 詳細過程是什麼？val loss 只是一個觀察的指標還是有拿來更新權重

Val loss 只是觀察指標，沒有拿來更新權重。

DDPO training 每個 step 的完整過程：

從 dataset 取一筆 (x, cond) — x 是 placement（只用來提供 port 位置），cond 是 graph 結構
Reverse sampling（50 steps）— 從 noise 生成 placement x_0，同時記錄每步的 log_prob
算 reward — reward = -hpwl_guidance_potential(x_0, cond)
算 advantage — advantage = (reward - EMA_mean) / EMA_std
算 DDPO loss — loss = -mean(trajectory_log_prob * advantage)
loss.backward() → optim.step() — 更新模型權重
只有第 5-6 步的 DDPO loss 會更新權重。

而 val loss 是在 print_every 時額外跑的：

拿一筆 val data，用 supervised 方式算 ||predicted_noise - true_noise||²
印出來讓你觀察模型的 denoising 能力有沒有被破壞
不會 backward，不會更新權重
所以問題就在這：模型只被 HPWL reward 驅動，沒有任何力量阻止它忘記怎麼 denoise。Val loss 只是旁觀者，眼睜睜看著數字飆升。

這也是為什麼「混合 loss」是最重要的改進方向——把 supervised loss 也加進去更新權重，就能同時保住 denoising 能力。

val loss 的比較對象是誰？

是 ground truth noise。

具體來說，train_graph.py 裡 print_every 時會跑 utils.validate()：

拿一個乾淨的 placement x_0（來自 val dataset）
隨機取一個 timestep t，加上已知的 noise ε 得到 x_t
讓模型看 x_t，預測 noise ε̂
val_loss = MSE(ε̂, ε)
所以 val loss 比較的是「模型預測的 noise」vs「實際加上去的 noise」。這是標準 diffusion model 的 supervised training objective。

val loss = 0.17 表示模型很準確地預測 noise（denoising 能力好）。val loss = 130,000 表示模型的預測跟真實 noise 差了十萬八千里（denoising 能力已毀）。

所以說你才說要用 supervised loss 限制跟原本模型之間的距離嗎

對，概念是這樣。不過有兩種不同的做法：

1. 混合 supervised loss（我之前建議的）

total_loss = ddpo_loss + α * supervised_denoising_loss
每個 step 同時算 DDPO loss 和 supervised loss，一起更新權重。這樣模型在追求低 HPWL 的同時，也被要求維持 denoising 能力。

2. KL penalty（DPOK 論文的做法）

total_loss = ddpo_loss + β * KL(π_new || π_pretrained)
直接限制新 policy 的分佈不能偏離 pre-trained model 太多。不管 denoising 好不好，只要行為跟原本差太多就懲罰。

兩者的差別：

混合 supervised loss：保護的是「denoising 能力」
KL penalty：保護的是「整體行為不要偏移」
效果類似，都是防止 catastrophic forgetting。KL penalty 更有理論基礎（來自 TRPO/PPO 的 RL 理論），但實作上混合 supervised loss 更簡單，因為我們已經有現成的 denoising loss。

可是限制不要更新太多不就是 PPO 和 TRPO 的做法嗎？能不能直接使用 PPO ？

對，你說得沒錯。其實 DDPO 原始論文（Black et al.）就有一個變體叫 DDPO-IS，用的就是類似 PPO 的 importance sampling + clipping。

但我們 repo 裡 ddpo.py 實作的是最簡單的版本（REINFORCE with baseline），沒有 PPO 的 clipping 或 trust region。

要加 PPO 的話，改動不大，核心差異是：

目前（REINFORCE）：

loss = -mean(log_prob * advantage)
PPO 版本：

ratio = exp(log_prob_new - log_prob_old)
clipped_ratio = clip(ratio, 1-ε, 1+ε)
loss = -mean(min(ratio * advantage, clipped_ratio * advantage))
需要多存一份 log_prob_old（更新前的 log prob），然後用 ratio clipping 限制每次更新的幅度。這就是 PPO 防止 policy 偏移太多的機制。

所以可以做，而且應該比現在的 naive REINFORCE 更穩定。要我把這個加到 plan 裡作為下一次 DDPO 實驗的改進方向嗎？

對了我想問 legalization 階段是啥，我忘了

Diffusion model 生成的 placement 會有 macro 之間互相重疊（overlap）的問題。Legalization 就是把重疊消除，讓 placement 合法化的後處理階段。

整個 eval 的流程是：

Reverse sampling — diffusion model 從 noise 生成初始 placement
Guidance — 用 HPWL 梯度微調位置（降低 wire length）
Legalization — 用梯度下降（opt-adam, 20000 steps）移動 macro 消除 overlap，同時盡量維持低 HPWL
Legality = 1.0 表示完全沒有重疊，0.99 表示還有一點點。Legalization 做的就是把這個數字盡量推向 1.0。

所以 adaptec1 的 legality 只有 0.919，代表 legalization 後仍有 ~8% 的 overlap 沒消除，這個 placement 品質是不合格的。

這是在 denoise process 中間執行嗎？還是後處理呢

是後處理。Reverse sampling 完全結束後才做。

時間順序：

Noise → [Reverse Sampling (1000 steps)] → [Guidance (20 steps)] → [Legalization (20000 steps)] → 最終 Placement
         diffusion model 生成              HPWL 梯度微調           消除 overlap
         不改權重                          不改權重                不改權重
三個階段都是在 inference 時執行，都不改模型權重，只改 placement 的座標。

1. Supervised fine-tuning 為什麼能改善表現？
Supervised loss 就是標準的 diffusion denoising loss：

L = ||ε_θ(x_t, t) - ε||²
給模型一個乾淨樣本 x₀，加 noise 得到 x_t，讓模型預測加的 noise ε。

為什麼繼續 fine-tune 能改善 ISPD 表現？

關鍵在 distribution shift：

large-v2.ckpt 是在非常通用的 synthetic data 上訓練的（包含各種大小、各種 graph 結構的 circuit）
我們的 fine-tuning data 是 v1.61，這批 synthetic data 的 graph 特徵（macro 數量、connectivity pattern）更接近 ISPD2005
Fine-tuning 等於做 domain adaptation——把模型的 learned distribution 從「通用 circuit」移向「ISPD-like circuit」
類比：一個會畫各種動物的畫家，你再給他 100 張狗的照片讓他練習，他畫狗的能力會提升，即使你沒有教他任何新技巧。

這就是為什麼 ablation（純 supervised）也能把 HPWL 從 48.69 降到 45.43（−6.7%）——不需要 reward signal，光是讓模型更熟悉 ISPD-like 的分佈就有效。

2. Reward 沒上升，為什麼 ISPD eval 還是改善？
這裡有兩個層面：

(a) Reward 是在 synthetic data 上算的，eval 是在 ISPD 上跑的
Training 時 reward 算的是：「模型在 v1.61 synthetic circuit 上的 reverse sampling 結果」的 HPWL + legality。這跟 ISPD2005 的 circuit 是不同的 graph。

所以 training reward 不動 ≠ ISPD eval 不動。模型可能在 synthetic data 上持平，但在 ISPD distribution 上進步了。

(b) Reward 波動太大，看不出趨勢
Batch size = 2，每次只看 2 個 sample 的 reward。就像擲 2 次硬幣就要判斷硬幣是否公平——variance 太大。

實際上，reward_ema_mean 從 −236 慢慢移到 −254，看起來是「變差」，但這主要是 EMA 從初始的 warm-up 階段收斂到 stable 值，不代表模型變差。

(c) DDPO 的真正貢獻在 ablation 對比中才看得到
Ablation (supervised only)	DDPO v2 (supervised + reward)
Avg HPWL (7 circuit)	45.43	44.65
這個 1.7% 的差距就是 DDPO reward 的貢獻。它很小，因為 reward signal 被 supervised loss + normalization 壓制了。但它是一致的（5/8 circuit DDPO 更好），不是 random noise。

用更直白的說法：DDPO 的改善確實微弱，大部分功勞在 supervised fine-tuning。 DDPO 的角色比較像「微調方向盤」，supervised loss 才是「引擎」。

3. Local reward 到底是不是干擾？
在目前的實作下，是的，主要是干擾。 但原因不是 local reward 這個想法不好，而是實作的位置有問題。

為什麼目前的 local reward 是干擾
Diffusion reverse process 的 timestep 可以分三個階段：

t=1000 (純 noise)  →  t=500 (粗略結構)  →  t=1 (最終 placement)
       早期                中期                  後期
在早期（t 接近 1000），predicted x₀ 的計算是：

predicted_x0 = (x_t - σ_t × ε_θ) / α_t
此時 σ_t ≈ 1, α_t ≈ 0，所以 predicted x₀ ≈ 放大後的 noise。對 noise 算 HPWL 然後拿來做 reward，等於告訴模型「你的雜訊擺得不好」——這完全沒意義，只會干擾 gradient。

但 local reward 在某些情況有用
實驗中 adaptec4 和 bigblue2 拿到三組最好成績：

bigblue2（23k macros，guidance 被關掉）：完全靠模型的 raw output + legalization。Local reward 鼓勵中間步驟就輸出好的 placement，在沒有 guidance 修正的情況下，這個訊號有價值。
adaptec4（1329 macros）：可能剛好 local reward 在後期 timestep 給了有效的 gradient。
如何讓 local reward 真正有用
有三個方向：

(1) 只在 last K steps 算 local reward

# 只在 t < 200 時算 (predicted x₀ 已經接近 final)
if t < 200:
    local_reward = hpwl(predicted_x0)
這是最簡單的修正。早期 timestep 的 predicted x₀ 沒意義，後期的才有。

(2) 用 timestep-dependent weighting

weight = (alpha_t) ** 2  # α_t 在早期接近 0，後期接近 1
local_reward = weight * hpwl(predicted_x0)
自然地讓早期 reward → 0，後期 reward 有影響力。

(3) 換成 consistency reward（不看絕對品質，看穩定性）

# 如果 predicted x₀ 在相鄰 step 變化不大 → 好（模型很確定）
consistency = -||predicted_x0[t] - predicted_x0[t-1]||²
這不要求早期就有好的 placement，只要求模型的預測穩定收斂。

建議
目前階段建議先拿掉 local reward，把有限的 GPU 時間花在更有 impact 的事情上（例如更多 training steps、更大 batch size、或嘗試其他改進方向）。如果以後要重試 local reward，用方案 (1)（只在 last K steps 算）最 cost-effective。

核心答案
這兩個是本質上不同的機制，local reward 失敗不代表 training loss 加 HPWL/legality 也會失敗。

關鍵差異：Policy Gradient vs Direct Gradient
DDPO Local Reward	Training Loss + HPWL
Gradient 類型	Policy gradient（reward detach，透過 log_prob 回傳）	Direct gradient（HPWL 直接 backward）
Variance	高（advantage 放大雜訊）	低（backward 自動穩定）
量級爆炸風險	有（v2.4 看到 1e10+）	無
Sample efficiency	低（RL 本質）	高（supervised 本質）
DDPO local reward 失敗的三個原因（reward 爆炸、variance 高、資訊量低）全部只存在於 policy gradient 下。Direct gradient 沒這些問題。

文獻依據：ReFL
其實教授的建議就是 ReFL (Reward Feedback Learning) 的核心概念——在 text-to-image diffusion 領域已經證明比 DDPO 好很多。機制就是「跳過 policy gradient，直接把 reward 當 supervised loss」。

額外佐證
目前最佳方法是 Ablation 10k (44.01)，純 supervised training。這證明 supervised learning 是這個 task 的主驅動力。加 HPWL/legality loss 是 supervised 的自然延伸，不是方向轉換。

風險
可能因為冗餘（ground truth 已低 HPWL）而效果有限——但不會 harm
Loss weight 需要調（建議從 α=1e-3, β=1e-2 起步保守測試）
早期 timestep 的 predicted x₀ ill-defined——可以用 alpha_t² timestep weighting 解決
結論
推薦嘗試。 可行性高、實作簡單（~20 行 code）、風險可控、與文獻先例一致。
