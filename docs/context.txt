### 3.1 對外（論文 / 教授 / 審稿人）唯一最強且站得住腳的主張

> **SVDD_layered = 44.845 ± 0.654，3 seeds，跑在 paper 自己的 frozen
> large-v2 checkpoint 上，零訓練、零新參數，3/3 seeds 全勝 paper 的 46.89。**

只有這條同時具備：(a) 同 checkpoint、(b) 有誤差棒、(c) 不需要訓練 → 不存在
「你 fine-tune 過所以不公平」的攻擊面。

### 3.2 Fine-tuning 結果（44.01 / 44.321）該怎麼講

**對 48.691 比，不要對 46.89 比。**
44.01 是「我們在 v1.61 上 fine-tune 過的模型、seed 300、n=1、原始 metrics.csv
已遺失」；46.89 是「他們未 fine-tune 的已發表數字、seed 400」。跨 seed、跨訓練
狀態、跨環境，三重不可比。

正確寫法： Ablation_10k vs 我們的復現 48.691 → −9.6%（同環境同 seed）。
錯誤寫法： 「Ablation 10k 44.01 beats paper 46.89 by 6.1%」← CLAUDE.md 與舊版
           context.txt 的原文，**已作廢，看到就改**。

### 3.3 為什麼特別強調這件事：專案已經被同一個坑咬過一次

2026-05-21，`svdd_plan_3.md` §1 把「Ablation_10k + opt = 44.01」寫成
「Paper 方法」，於是 Phase 3 拿 SVDD 去比一個**使用者自己 fine-tune 出來的
最強 checkpoint**，得到 Δ=+0.37% → `svdd_report_3.md` §11 直接宣告
「inference-time search 整個方向 dead end」。是使用者當場抓到
（"那個是我之前 finetuning 的結果"）才翻盤：改在 large-v2 上重跑 → 45.10 →
再補 multi-seed → 44.845 ± 0.654，**從死路變成全專案對外最強的結果**。
一個 framing 錯誤燒掉一整個 phase。

現在同一個陷阱**以反方向存在**於 CLAUDE.md 與舊 context.txt（拿自己的
fine-tune 結果去打 paper 的未 fine-tune 數字）。寫任何 plan 時，「baseline」
必須明講是 paper 的 46.89、還是我們的復現 48.691、還是我們自己的 best。

### 5.1 DDPO — policy gradient fine-tune（run 1–5，2026-04）  【關閉】
docs/{plan,report,next}/ddpo_*
- run1 REINFORCE、legality_weight=0（設定失誤）→ catastrophic forgetting, val_loss→264
- run2 PPO clipping + supervised mix + legality → **v2 = 44.65**（DDPO 最佳）
- run3 seed ensemble + **supervised-only ablation 10k = 44.01**（發現 supervised 才是主力）
- run4 local reward 加 legality → 46.503（legality potential 在早期 timestep 爆到 1e10）
- run5 last-K local reward → 45.857（修好爆炸但仍不如 v2）
- **判定：關閉。** local reward 三個變體全較差；根因已診斷（早期 timestep 的
  predicted_x0 本身就是 ill-defined 的噪音估計；batch=2 的 policy gradient 變異太大）。
- **副產品：發現 `from_checkpoint` 雙重路徑 bug**（§8.2），影響此前所有 eval。

### 5.3 SVDD-PM — inference-time particle search（Phase 1–5，2026-05-19 ~ 05-24）【成立】
docs/{plan,report,next}/svdd_*（report 有 1–5 五份）

  SVDD **單獨**不能取代 opt guidance（66.531 vs 復現 48.691）→ 必須 layered

  特別敏感（std 5.34，其他 circuit < 2.6）→ single seed 會看到假的「結構性退步」
- **⚠️ `svdd_report_3.md` §1 與 §11 至今仍寫著「inference-time search 正式 dead end」，
  從未修訂，與 report_5 直接矛盾。先開那個檔的人會得到完全相反的結論。**
  同樣作廢但仍在磁碟上的還有 `svdd_next_2.md` §3.1。

### 5.4 CoDe — blockwise best-of-N（2026-05-24/25）  【成立】
- 45.216 ± 0.469（3 seeds），與 SVDD 統計上等價
- 只比 SVDD 快 17%（因為 wall-clock bottleneck 是 opt 的 20 次 inner SGD，不是 K-particle）
- bigblue4 顯著輸 SVDD 4.42（大 circuit 偏好「每步都探索」而非「每 100 步 fork 一次」）
- seed 302 的 bigblue3 legality 掉到 0.929（argmax 較激進，偶爾掉進 legalizer 修不回來的洞）

### 5.5 TDS — twisted SMC sampler（2026-05-25）  【成立】
- 45.081 ± 0.376（3 seeds），**方差最低**：bigblue3 std 從 SVDD 的 5.34 → 0.16（−97%）
- ESS-based resample 讓不同 seed 殊途同歸；賣點是「95% CI 比 SVDD 窄 40%」
- 順手修掉 codebase latent bug：`reverse_guidance_opt_force` 的
  `alpha_cost.backward()` 在 B>1 不能跑（改 `.mean()`，B=1 行為不變）

**§5.3–5.5 的共同結論**：三個機制上完全不同的 selection rule（per-step softmax /
per-100-step hard argmax / SMC importance + ESS）收斂到同一個天花板
（−3.6% ~ −4.4%，全距 0.79% vs seed std 0.4–0.6）→ **搜尋預算重要，選擇規則不重要**。
這是乾淨且可發表的負面結論。negative controls 也齊備（SVDD 取代 opt = 66.531；
完全無 guidance = 84.854）。

## 7. CLOSED — 已關閉的方向與殺死它的證據
--------------------------------------------------------------------------------

1. **DDPO 與所有 local-reward 變體**
   5 個 run。v2 PPO 44.65 是這條線最佳，但三個 local reward 變體全較差
   （45.804 / 45.857 / 46.503）。根因已診斷：早期 timestep 的 predicted_x0 是
   ill-defined 的噪音估計、batch=2 的 policy gradient 變異過大、reward 量級可爆到 1e10。

2. **AddLoss / ReFL-style 輔助 loss —— 被兩個獨立實驗證偽**
   (a) fine-tune 端：AddLoss v1 45.387 / v2 45.236，訓練指標全面改善但 ISPD 沒跟上；
   (b) **從 step 0 端**：from-scratch Run Y 45.121 vs Run X 45.053，Δ=+0.068。
   加上 DDPO local reward 的失敗，**三線獨立收斂**到同一個結論：
   **輔助 HPWL/legality 訊號對這個任務是冗餘的，因為 ground-truth placement 本身
   已經是低 HPWL 且合法的**。這是乾淨、可發表的負面結果。

3. **Flow matching，連帶 drifting model**
   同預算 70.028 vs DDPM 45.053。死因是 OOD 泛化（V>=723 起全面崩），不是 guidance
   調參問題 —— 差距 25 個 HPWL 單位不是加長訓練或調 guidance 的量級。
   Drifting model 同屬 few-step deterministic 家族，預期同樣弱點，一併關閉。

4. **EDA-generated dataset**（`eda_dataset_plan_1.md`，教授 meet_0620 建議 4）
   四個方向中工程量最大（DREAMPlace 安裝 + format converter，2–3 天），而且
   **它自己的 plan §4 就預先登記了 kill test**：synthetic 原 label 是 by-construction
   near-optimal，EDA label 品質若更差反而傷。在其他更便宜的方向都還沒收割完之前，
   正式關閉。

5. **申請更大的 GPU**
   舊 context.txt 的 pending item F。**它的動機是 DDPO 的 batch size，而 DDPO 已死。**
   而且 GPU 已經自己換成 32.6 GB 了（§2）。bigblue2 的 guidance OOM 現在是
   「在新 GPU 上重量一次」的問題，不是採購問題。

**不建議完全關閉的**：from-scratch。Run X 以 1/6 步數從隨機初始化達 45.053，

## 8. 已知問題 / GOTCHAS
--------------------------------------------------------------------------------

### 8.1 【NEW, BLOCKER】GPU / torch 不相容 —— 見 §2
sm_120 vs arch_list<=sm_90。`torch.cuda.is_available()` 騙人，會回 True。
修好後**必須先重跑 Run F 驗證（預期 44.321）**再信任任何新數字。

### 8.2 `from_checkpoint` 雙重路徑 bug（老坑，仍然存在）
`eval.py` / `train_graph.py` 都做 `os.path.join(cfg.log_dir, cfg.from_checkpoint)`。
`log_dir=logs/diffusion_debug`，所以傳
`from_checkpoint=logs/diffusion_debug/X/latest.ckpt` 會變成
`logs/diffusion_debug/logs/diffusion_debug/X/latest.ckpt` → **silent fail，
模型是隨機初始化跑完的**。
一律用**相對於 log_dir** 的路徑：
    從 saved run:  `from_checkpoint=v1.61-ddpo.<method>.61/latest.ckpt`
    從 pretrained: `from_checkpoint=../public-models/large-v2/large-v2.ckpt`
**每次都要驗證 eval log 內出現字串 `successfully loaded state dict for model`**；
若出現 `no checkpoint at ... found` 就是路徑錯了。

### 8.3 eval 目錄碰撞 —— 已造成 6 筆結果永久遺失
run dir 命名是 `<task>.<method>.<seed>`，**不含 from_checkpoint**，導致七個
fine-tuning eval 全部寫進同一個 `ispd2005-s0.eval_macro_only.300/`，只有最後一個
（AddLoss v2）倖存。Ablation_10k (44.01)、DDPO v2 (44.65)、AddLoss v1、
DDPO v2.3/2.4/2.5 的原始 metrics 已遺失。
**checkpoint 都還在，所以是重新 eval 而非重新訓練**（除了 §4 標 LOST 且 ckpt 也沒了的）。
修法：讓 from_checkpoint 進入 run dir 名稱（~20 min）。

### 8.4 Hydra override 語法
`guidance@_global_=opt`、`legalizer@_global_=opt-adam`、`mode@_global_=ddpo`
（**必須有 `@_global_`**）。新 key 要 `+` prefix：`+start_sample=5`、
`+skip_guidance_threshold=10000`。

### 8.5 ISPD task 名稱
使用者 parse 好的資料在 `datasets/graph/ispd2005-s0/`，用 `task=ispd2005-s0`。
code 內對 `dataset_name == "ispd2005"` 的特例（把 is_ports 歸零）**不會**觸發。

### 8.6 bigblue2（23,084 macros）
Guidance 的 V×V 矩陣在舊的 24 GB 上必 OOM → 一直用 `+skip_guidance_threshold=10000`
自動跳過 guidance（**只跳 guidance，不跳 legalization**；legalization 本身塞得下，
但要 ~100 min）。因此 bb2 一直是 57–66 vs paper 38.8，**是唯一從未勝過 paper 的 circuit**。
新的 32.6 GB 使 full guidance 變成邊緣可行（§2），值得重試一次。
技術提示：`guidance.py:49` 的 `legality_guidance_potential_tiled`（block_size=16384）
已在 `legalization.py:52,148` 與 `sc_placement.py:281` 實際使用（**不是死碼**），
但 guidance 路徑（`models.py:1916, 1954`）與三個 search reward（`:1621, :1726, :1801`）
走的是**未 tiled 的版本**。改走 tiled 版是低風險改動，因為該 kernel 已在
legalization 上實戰驗證過。

### 8.7 PyG batched edge_index bug
`networks/layers/wrapper.py` 對 B>32 有結構性問題，觸發
`gatv2_conv.add_self_loops` 的 scatter index 越界。
- batch=64 訓練會炸 → from-scratch 全系列被迫用 batch=32（half-exposure caveat）
- SVDD K=8 同一個 bug → 一律用 K=4 規避
- DataAug Run B 就是死在這個（`add_self_loops` scatter crash）
- commit `ad5553a` 加了 BatchWrapper chunking 修正，但**升級 torch 後要重新確認**

### 8.8 系統 CPU 競爭會汙染所有 runtime 數字
其他 user（ansys.e, redhawk+）可讓 eval 慢 5–13×。GPU 可能顯示 11% util 但實際是
CPU-bound。eval 異常慢時先看 `uptime` 與 `top`。
**這已經汙染了記錄中的 generation_time，直接引用會產生物理上不可能的表**：
baseline adaptec1 = 419.6 s（2026-03）vs Run F 同組態 133.4 s（2026-05），3.1× 差距。
照抄的話 SVDD (132.5 s) 會看起來比 opt-only (419.6 s) 還快，而它每個 reverse step
要多做 K=4 次前向 —— 審稿人會直接拒。
**誠實的同日同 checkpoint 量測**：Run F 3079 s vs Run E 3455 s = **+12.2% overhead**。
每 seed 7-circuit 實測：CoDe 43.5 min、opt-only 51.3 min、SVDD 57.6 min、
TDS 95.6 min（其中 81 min 花在 bigblue4 一個 circuit）。

### 8.9 generate_parallel.py 的 num_workers
預設 64 會 OOM 並踢掉 SSH。用 4，或改用單進程的 generate.py。

### 8.10 `placements/macro-ispd/` 不是我們跑的
那是 **paper 作者**的結果（checkpoint `v2_gmix1.6_2x...ckpt`），與 paper Table 10 完全吻合。

### 8.11 Val loss ≠ ISPD 表現
Ablation 10k 的 val loss 從 step 1000 到 10000 是**上升**的（0.10→0.17），
但 ISPD 反而變好。對 v1.61 稍微 overfit 有助於 ISPD transfer。
→ 不要用 val loss 當 early stopping 訊號。

### 8.12 v1.61 訓練資料比 ISPD 最小的 circuit 還小
v1.61 系列 max_instance=400 macros，而 adaptec1 有 543。**「v1.61 比較接近 ISPD 尺度」
這個假設是錯的**。v2.61 的 max_instance=1600 才涵蓋大部分 circuit。
所有 ISPD 結果本質上都是 OOD extrapolation（這也是 flow matching 的死因）。

## 9. 統計紀律（踩過坑才立的規矩）
--------------------------------------------------------------------------------

1. **每個主要結論至少 3 seeds。** 來源：Phase 4 的 single-seed bigblue3 = +14.2%
   曾催生三個「SVDD 結構性弱點」假說，3-seed 之後變成 −3.0%（純 bad luck）。
   本專案目前**違反這條規矩最嚴重的地方就是 leaderboard 前四名**（全部 n=1，
   全距 0.636 < std 0.654）與 §6.3 的那條禁令。
2. **n=3 要用 t 不是 z。** `svdd_report_5.md` 的 95% CI [44.11, 45.59] 用了 z=1.96；
   正確的 t 區間（t_.975,df=2 = 4.303）是 **[43.22, 46.47]**。
   結論仍成立（46.47 < 46.89），但邊際比宣稱的薄很多。
3. **同 seed 的比較要用配對檢定。** `code_report_1.md` 用非配對檢定判 CoDe vs SVDD
   「不顯著 (t≈0.80)」；配對下 SVDD 三個 seed 全勝（+0.264/+0.590/+0.261），
   paired t = 3.40, p≈0.077 → 文件**低估**了 SVDD 對 CoDe 的優勢。
   （TDS vs SVDD paired t = 0.40，這兩個才是真的無法區分。）
4. **不要事後推翻預先登記的判定門檻。** 已經發生兩次：
   `addloss_plan_2.md` 把 44.5–45.39 列為「繼續」，結果 45.236 落在區間內卻仍被放棄；
   `ddpo_plan_5.md` 設 >=45.80 為「放棄」，v2.5 得 45.857 只超過 0.057 就直接放棄，
   沒試 contingency K=10。
5. **bigblue2 會翻轉結論的正負號。** Paper 的 8-circuit 平均是 45.88；我們 bb2≈57 時
   8-circuit 變成 SVDD 46.37 / TDS 46.57 / CoDe 46.69，**全部輸給 paper +1.1%~+1.8%**。
   損益兩平需要 bb2 <= 53.1 / 51.5 / 50.5；若能達 paper 的 38.8 則是
   44.09 / 44.30 / 44.42（−3.2%~−3.9%）。**任何 8-circuit 表都必須先解決 bb2。**
6. **論文的致命缺口：沒有 matched-compute best-of-N 對照。** SVDD/CoDe/TDS 用 K=4，
   審稿人必問「那把 paper 的 opt guidance 跑 4 個 seed 取最好呢？」——從未跑過，
   因為 opt-only baseline 只有一個 seed。若 best-of-4 opt-only 落在 44.8 附近，
   搜尋的貢獻就縮水成「同品質、1.12× 而非 4× 計算量」，是完全不同且弱很多的論文。
   **成本為零**（同 4 個 baseline run 同時當 baseline 與對照）。
