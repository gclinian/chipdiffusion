## 三、我學到的機制（這是有價值的部分）

**1. 這條 pipeline 的品質是 guidance + legalizer 決定的，model 幾乎不重要。**
四種來源的 model（原論文的、微調過的、從零訓練的、加 augmentation 的）在同一套 guidance + legalizer 下，
結果全部落在同一個帶內。這解釋了為什麼半年來換 model 的嘗試全部沒差。

**2. 確定性採樣在大 circuit 上會崩，這是 flow matching 輸的主因。**
我把 guidance 關掉、只看 model 本身：DDPM 用確定性採樣（DDIM，η=0）在 bigblue4 上比隨機採樣**差 61%**，
三個種子的結果幾乎一樣（±2%）。Flow matching 的目標函數再讓它多差一倍多（2.2×，±0.2）。
換句話說：這個任務的 OOD 穩健性（訓練最多 1600 個 macro，測試 8000+）靠的是**每一步注入的隨機性 + gradient guidance**，
不在 model 裡。所有「少步數、確定性」的新生成範式（flow matching、drifting、consistency 那一家）在這裡先天不利。
這是我這半年唯一一個**新的、量化的、可重複的正向發現**。

**3. 「贏原論文」這個靶本身會漂。**
原論文的 checkpoint 在我們現在的硬體上（RTX 5090、新版 torch）跑出 45.99，比它自己發表的 46.89 好 2%。
任何人在新硬體上跑任何東西都會「贏 paper 2%」。領域裡拿固定數字當靶的比較，都有這個問題。

## 四、為什麼這個 benchmark 已經看不出方法差異

同一個 checkpoint、同一套設定，只換亂數種子跑六次，六個 circuit 的平均值會在 **±1.0** 左右擺動
（平均約 31，所以是 ±3%）。單一 circuit 更大：adaptec2 擺 ±7%、bigblue3 ±6%。

這代表：**任何小於 3% 的「改進」，用三個種子根本分不出是真的還是運氣**；要把一個真實的 3% 改進做到統計上站得住，
要跑二十個種子。而過去領域裡、包括我們自己在五月宣稱的那些改進，全部在這個範圍內。
教授 06/20 說「可能已經到極限了」，數據證實了：不是方法到極限，是**這個 benchmark 的解析度到極限**。

## 五、領域這一年在做什麼

2025–26 在 ISPD2005 上有進展的，全是**構造式搜尋**（wire-mask：macro 依序放，每一步選讓 HPWL 增加最少的格子），
外面套演化或 LLM 來搜擺放順序（EGPlace ICML'25、OrderPlace ICML'26）。**沒有生成模型。**

| | 原論文 | 我們復現 | OrderPlace |
|---|---:|---:|---:|
| adaptec1（543 macros）| 9.19 | 9.03 | **5.75** |
| bigblue1（560）| 2.64 | 2.63 | **2.00** |
| 六個 circuit 平均 | 31.27 | 32.06 | **29.98**（−4%）|
| bigblue4（8,170）| 141 | 129.5 | **沒跑**（只放 1024 個）|

搜尋方法在小 circuit 上大贏（−24% ~ −37%），中型持平，大 circuit 沒人跟 diffusion 比 — 但也沒人在比。
diffusion 這條線在這個 benchmark 上的競爭位置：小的輸、大的沒對手也沒觀眾。

## 六、我抓到的一個錯誤（主動講，因為它是這半年最重要的事）

三到八月我報告過兩個「贏」：微調後 44.01（贏 paper 6%）、SVDD 搜尋 44.85（贏 4.4%）。
**這兩個都不成立。** 它們是對一個壞掉的 baseline（48.69）比出來的。那個 baseline 是三月的單次 run，
組態記錄後來被覆蓋掉無法查證，adaptec2 跑出 39.06、合法度只有 0.93 — 而新環境六個種子的 adaptec2 是 27–34、合法度 0.94–0.98。
換了 GPU 之後重跑，baseline 是 45.99 不是 48.69；把微調和搜尋放在同一個環境、同樣的種子下配對比較，差異都是零。

這件事我想強調的不是「我錯了」，是：**發現它、修正它、把規則寫進專案（任何比較必須同環境、同種子、至少三個種子）**，
是這個專案現在最有價值的方法論產出。如果沒抓到，我會帶著兩個假的結果去投稿。

## 七、還剩什麼可以做，以及為什麼我不建議

| 選項 | 內容 | 我的看法 |
|---|---|---|
| A. 調 guidance / legalizer 的超參數 | 57 個 run 從沒動過這幾個參數 | 3–4 小時可以跑完當作關門實驗。但它測的是「為什麼 model 不重要」，不是一條會贏的路 |
| B. bigblue2 開 guidance（新卡 32 GB 可能放得下）| 一次 eval | 工程性質；補一個 8/8 的表，不改變結論 |
| C. 換 benchmark（IBM / ICCAD04 / mixed-size）| 重建 model、baseline、legalizer 校準 | 成本等於一個新題目。既然要開新題，我希望選一個上限更高、我更有動力的 |
| D. 再給 best-of-N 加種子 | 要 ~20 個種子才能解析 0.7 的差距 | 四倍成本換一個解析不出來的 2%，不值 |

**我不建議的理由總結**：剩下的路要嘛是收尾（A、B），要嘛是新題目（C）。這個題目提出的問題 —
「能不能用更好的 model 或 sampler 贏 ChipDiffusion」— 已經有答案了。

## 九、教授可能會問的問題（我的回答）

**「你會不會收太快？」**
不會。這一輪 12 條軸、88 個 eval，每個都先寫好門檻再跑；主要結論都是三個以上種子配對比較。之前任何一輪都沒這麼嚴。

**「五月不是說 SVDD 贏 4.4%？」**
對，那是對壞掉的 baseline 比的。同環境重測是 −0.18 ± 1.28，等於零。抓到這個錯是我這半年最重要的一件事。

**「那 flow matching 為什麼輸，你確定嗎？」**
確定。我把 guidance 關掉單獨測 sampler：確定性採樣在大 circuit 差 61%，三個種子誤差只有 ±2%；FM 的目標函數再差 2.2 倍。
這是整個專案裡最乾淨的結果。

**「換 benchmark 再試呢？」**
那等於新題目 — model、baseline、legalizer 都要重做。如果要開新題，我想選一個上限更高的。

**「Drifting model 你沒實作就關掉？」**
它是一步生成器：沒有 diffusion 步驟、沒有隨機性。我們已經證明「拿掉每一步的隨機性」本身就讓大 circuit 崩 61%，
一步生成把隨機性全拿掉，只會更糟。而且它的 kernel 頻寬跟輸入維度綁在一起，訓練 400 個 macro、測 8000 個時會飽和。
文獻裡沒有任何 drifting 論文測過「輸入比訓練大」的情況。

**「EDA 產的資料你為什麼不做？」**
因為 Run X 證明訓練資料來源不影響結果 — 從零用合成資料訓練的 model 跟原 checkpoint 沒差。
瓶頸在 guidance + legalizer，換 label 來源不會動到那一層。

**「那這半年的產出是什麼？」**
一個紮實的「否」、一個新的機制發現（隨機性 + guidance 是 OOD 穩健性的來源）、一個被抓出來的方法論錯誤和
對應的規則、一套可重複的實驗紀錄系統。這些會變成一份文件。

## 附：名詞（我自己要能解釋的）

- **HPWL**：所有 net 的 bounding box 半周長總和，越小代表線越短。×10⁵ 是單位。
- **Legality / 合法度**：macro 之間不重疊、不出界的程度，1.0 = 完全合法。
- **Guidance**：diffusion 每一步去噪時，額外對「目前的擺放」做幾次梯度下降，把 HPWL 壓低、把重疊推開。
- **Legalizer**：生成完之後，再跑兩萬步梯度下降把剩下的重疊消掉。
- **Seed / 種子**：亂數起點。同設定換種子結果會不同；差異小於這個擺動就等於沒差。
- **配對比較**：同一個種子下，方法 A 減方法 B，再看三個種子的平均和擺動。比各自平均再相減準。
- **OOD**：測試的 circuit 比訓練資料大很多（訓練最多 1,600 個 macro，測試到 23,084）。
